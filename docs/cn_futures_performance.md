# 国内期货交易热路径性能

本次优化保留单业务线程与异步落盘结构，针对两个已经测出的瓶颈：历史订单表扫描，以及业务线程上的原始回报／发送前审计 JSON 构造。CTP 与易达共用风控索引和后台审计实现，没有新增线程或 IPC。

## 改动

`TradingCore` 保留完整订单历史，另外维护未结订单集合及未确认手数总计。每个订单状态变化经同一入口更新集合和总计，包括恢复、本地拒绝、部分撤单和事实成交。报单手数限额读取缓存总计，自成交与待开仓检查只遍历未结集合；集合容量随未结峰值保留，不再随历史订单数持续增长。

未结的依据是 `remaining() > 0`，包含已经收到 Filled / Cancelled 终态、但尚未收到全部事实成交的订单。不能仅按订单状态移出集合，否则会提前释放限额、开仓预占与自成交保护。合约规则在预检时直接借用，避免每次克隆期货／期权元数据。

原始 CTP／易达回报通过有界队列传递独立的原生结构体副本，后台线程再构造 JSON、脱敏并落盘。逐笔和批量发送前审计也只复制必要请求数据入队，归一化 Prepared 记录在后台构造。发送意图时间仍在业务线程采集，避免后台排队时间改变订单的首个接收时间。单条原始易达回报的业务线程分配由 79 次变为 1 次；发送前审计由 38 次变为 5 次。JSON 的分配工作被转移到既有写盘线程，并未消失。

记录格式、证据顺序、同步 WAL WriteBatch、队列满／写盘故障停止，以及 `sync_before_send` 的语义保持一致。默认报单与回报仍为异步落盘，保留未落盘队列的崩溃窗口。完整持久化说明见 [订单持久化](cn_order_persistence.md)。

## 本地基准结果

2026-11-11，AMD EPYC 7642 共享主机，业务线程固定 CPU 190，后台线程保留原进程 CPU 集合。优化前后均为默认 feature 的 release 构建，优化前基线为 `3273f9d9` 的交易代码，三轮交错运行优化前／后程序。每轮每个用例采集 15 批 × 128 次，计时包含线程内分配计数开销，未加载 SDK、未连接网络、CPU 未隔离。下表取三轮对应分位数的中位数，原始数据见 [JSON 记录](benchmarks/cn_futures_hot_path.json)。

| 测量项 | 原 p50 | 优化后 p50 | 原 p99 | 优化后 p99 |
| --- | ---: | ---: | ---: | ---: |
| 准备＋本地拒单，起始历史 0、未结 0 | 3.045 µs | 1.543 µs | 10.229 µs | 8.306 µs |
| 准备＋本地拒单，起始历史 10,000、未结 0 | 242.199 µs | 0.842 µs | 469.391 µs | 1.713 µs |
| 准备＋本地拒单，起始历史 10,000、未结 8 | 232.281 µs | 1.603 µs | 422.942 µs | 2.225 µs |
| 原始易达回报审计入队 | 25.909 µs | 0.441 µs | 64.973 µs | 3.217 µs |
| 发送前审计入队 | 6.042 µs | 0.851 µs | 23.354 µs | 10.430 µs |

“准备＋本地拒单”包括意图构造、规则／风控检查、预占、引用分配及确定未发送的拒单退款；每批由标注的历史数量开始，再新增 128 条本地拒单记录。回报／审计用例测量生产者入队，批次间单独等待真实 RocksDB 写盘完成，计时不包含该等待。

这些结果只描述上述本地代码路径。SDK 发送、网络与柜台处理、实际策略决策、整机稳定吞吐和生产环境尾延迟仍需单独测量。原始回报解析、字符串身份与订单快照仍有分配；诊断 `state` 和完整重连恢复仍处理完整账户历史。

## 复现与回归

```bash
LIBCLANG_PATH=/absolute/libclang-directory \
  cargo bench --locked -p cn_futures --bench native_hot_path -- \
  --cpu 190 --samples 15 --ops 128

# 同一程序重新使用业务线程构造审计 JSON，便于单独比较审计开销。
LIBCLANG_PATH=/absolute/libclang-directory \
  cargo bench --locked -p cn_futures --bench native_hot_path -- \
  --cpu 190 --samples 15 --ops 128 --legacy-audit
```

CPU 编号应改为本机允许使用的核。程序只创建独立临时 RocksDB、运行合成订单／回报并正常关闭和删除该临时目录；不读取交易凭据，不加载厂商库，不发送真实订单。`--legacy-audit` 只影响基准中的审计构造方式，运行时保持唯一的生产路径和数据契约。

本轮回归：`cn_futures` 双 SDK 96 项、`persist_common` 15 项、`persist_manager/runtime` 74 项测试通过。新增覆盖终态先到时继续保留风控、迟到／重复成交与过时委托回报、恢复与批量审计失败回滚后的索引一致性，以及后台序列化后的完整长 ID、浮点位值、尾部回报、脱敏和生产者时间戳。CTP 桥接与易达 42 个逐场景重开 RocksDB 的 SDK 场景及已有仓位保护场景通过；这些 SDK 场景均为离线仿真。没有生产部署。
