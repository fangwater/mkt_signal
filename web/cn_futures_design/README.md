# CN Futures 执行架构展示页

这是独立、无外部依赖的设计页。包含交互架构图、交易兼容表、确定性订单推演、手动性能成本模型与 Markdown 导出。**页面不连接交易运行时，所有页面订单事件均为演示。**

CTP 6.7.11 交易初版已实现在 `crates/cn_futures`，构建和仿真接入说明见仓库 `docs/ctp_trade.md`。已完成本地核心、桥接和官方 SDK 离线验证，尚未连接真实中金所柜台。易达 1.188.78.0 原生交易初版已实现，见 [易达接入说明](../../docs/yida_trade.md)，通过本地合成 SDK 桥接联测，待配套柜台仿真联调。

直接打开 `index.html` 即可使用，也可以只提供这个目录：

```bash
python3 -m http.server 18761 --bind 127.0.0.1 --directory web/cn_futures_design
```

浏览 `http://127.0.0.1:18761/`。该服务只提供设计页文件，不需要凭据，不启动任何交易进程。

## 已确认的接入范围

| 范围                     | 接入设计                                                                |
| ------------------------ | ----------------------------------------------------------------------- |
| 中金所 CFFEX             | CTP 原生交易 API；IF、IH、IC、IM、TS、TF、T、TL 期货                    |
| 上期所 SHFE              | 易达原生交易 SDK；以实际账户权限及活跃合约为准                          |
| 上海国际能源交易中心 INE | 易达原生交易 SDK；以实际账户权限及活跃合约为准                          |
| 行情                     | 来源独立，暂按 CTP 考虑；本次聚焦交易兼容，不展开易达行情或行情接入实现 |
| 期权                     | 不在首期范围                                                            |

每个账户 / 风控域一个运行实例；一个实例明确绑定一个原生交易后端及其交易所白名单。易达实例可以同时拥有 SHFE 和 INE，两者的合约、仓位与订单仍按交易所区分。页面的交易所切换用于说明范围，不代表自动路由或自动切换生产账户。

若不同接入后端实际共用同一资金账户，需要先确定账户级风险状态的唯一所有者与对账来源，不能让两个实例分别把同一份可用资金全额视为自己的额度。

## 业务运行模型

```text
独立行情事件入口 ───────────────┐
                              ↓
原生交易回报 / 查询 → 有界入口 → 单核业务 loop
                              ├─ 策略 / 执行意图
                              ├─ pre-trade 风控与预占
                              ├─ 委托 / 今昨仓 / 风险 / 会话状态
                              └─ 原生交易适配器 → CTP 或易达 SDK
                              ↓
                        后台日志 / 持久化 / 监控
```

“一个 loop”指业务状态只由一个线程修改。标准 CTP SDK 通常有内部网络和回调线程；易达原生 listener 回调复制事件，经有界入口交给业务线程；登录追平以 `notifyCaughtUp` 和本地完整对账为准。

策略、风控和执行模块之间使用直接函数调用。行情源到实例的实际运输方式暂不展开，不能将“核心模块间 0 IPC”解读为行情源、后台服务或 SDK 内部完全没有线程交接。

回调结构体在回调有效期内拷贝或转换，不能持有 SDK 所有的临时指针。单生产者确认后可选 SPSC；多生产者使用适当的有界 MPSC，不能为降低开销而破坏生产者契约。应保留同源顺序；行情、交易、查询之间不假设全局时间顺序。

业务 loop 对每路事件设置处理预算，避免行情、查询或某一路回报饿死其他事件。流控应覆盖共享账户的全部订单和撤单，而不是每个策略各自独立计算。无需把网络读取、配置读取、日志或磁盘刷盘放入业务 loop。

## 一套核心交易契约

适配器映射到同一套当前内部交易意图和事实事件，不新增平行版本或版本化内部 IPC。

- 交易意图保留部署账户作用域、交易所、合约、买卖方向、开平、手数、价格 tick、有效方式与本地关联 ID；当前不接加密策略归属。
- 核心以明确的价格精度和整数手数管理委托；合约参数与权限来自 SDK；CTP 使用连续交易状态，易达首期依赖原生权限 / 有效期 / 校验，没有已验证的连续交易状态门控。现有历史回放乘数表不能直接视为实时交易授权或完整规则来源。
- CTP 与易达分别处理原生结构体、错误、身份关联和会话。保留真实原始订单及成交标识，唯一键的作用域按 SDK / 柜台契约核实。
- 易达原生函数、字段与登录追平依据公开 1.188.78.0 头文件实现；回调内查询、断线重放顺序和跨交易日行为仍需实际柜台验证。
- 已绑定后端发生故障时，阻断新开仓并恢复；不自动转投另一个交易柜台。

## 正确性约束

1. 在 API 调用前，完成风控、委托登记与预占。明确未受理的本地错误可以幂等回滚；发送结果不明时保留占用并查询，不能盲目重报。
2. API 返回与异步委托确认分别处理；成交只依据事实成交或经核实的柜台成交语义核销。
3. 上期所 / INE 的今昨仓分别管理，按明确策略拆成平今 / 平昨子单，各子单独立经历报单、拒单、成交与撤单，不能假设原子成交。CTP 中金所的具体开平指令和手续费归属按实际柜台规则映射，不照搬上期所。
4. 撤单请求不立即释放冻结；根据成交与终结回报核销未成部分。成交与撤单竞态、迟到事件、重复回报不能重复记账或使终态倒退。
5. 多空仓、冻结今仓、冻结昨仓和未成开仓额度应分别表达；演示页仅展示一侧简化账本，不等于完整生产持仓模型。
6. 原始成交事实幂等应用。恢复查询快照不是新增成交，不能将快照数值反复累加；应依据原生恢复契约确定快照、增量和完成屏障。
7. 连接中断不清除本地订单和占用。会话恢复、事实回放、委托与持仓对账、规则就绪全部完成后才解除新开阻断。
8. 夜盘保留柜台交易日与自然日期，按经验证的交易日历、时段和交易状态工作，不以 UTC 午夜或自然午夜直接重置仓位。
9. 可靠事件入口溢出时必须通过独立可见的故障标记进入待恢复；不能静默丢失事实，也不能用重连或清空队列代替对账。连接允许时保留必要撤单能力。
10. 配置以完整快照在业务线程应用；可靠订单事件有序输出。异步日志不等于掉电可靠，下单前持久化和刷盘策略须另外决定，不能宣称无丢失。

## 页面推演

可以播放、暂停、单步与重置，切换后端 / 交易所会清空演示状态：

- 正常成交：3 手订单，先成 1 手、重复成交去重、再成 2 手。
- 风控拒绝：额度 2 手，意图 3 手，报单调用数为 0。
- 本地调用失败：预占 3 手，明确失败后释放；发送结果不明不在此演示分支内。
- 部分成交后撤单：成交 1 手，撤单请求仍预占 2 手，确认后释放未成余量。
- 平今平昨拆单：上期 / INE，初始今 1 昨 2，拆成两个子单分别核销；从 CTP 页面选此场景会显式切换到易达 / SHFE。
- 断线恢复：保留占用，恢复证据核对为成 1 剩 2，完成屏障后回到 Ready。
- 入口溢出：状态进入 NeedsReconcile，保留占用，新开保持阻断。

这些是核心语义设计，不是已通过柜台联调的生产状态机。所有合约代号为产品级示意，没有真实合约月份、账户或订单。播放间隔只是展示节奏。

## 性能模型与验收

初始显示“无实测性能数据”。手动套用示例假设后才显示成本推演：

```text
参考分拆路径 = 本地业务处理 + 3 × (IPC 传递 + 排队 / 调度) + 原生 API 调用
单 loop 路径 = 本地业务处理 + 原生 API 调用
```

3 次交接是解释成本的参考拓扑，不声称整个现有仓库统一采用该拓扑。输入只是手动假设；模型不包含 SDK 内部排队、网络、柜台或撮合，不能推导真实 p99。也不将厂商公布的柜台穿透性能当成本系统端到端延迟。

实际测试使用同机、同数据、同策略、同风控语义，分别测量入口到报单调用、API 调用时长、报单到异步确认和事件积压，并报告 p50 / p99 / p99.9、CPU 占用及饱和负载。覆盖开盘突发、长尾策略计算、夜盘切日、查询响应和落盘压力。使用单调时钟；SDK 调用返回不代表数据已从网卡发出。
